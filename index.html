Core Focus

제가 반복해서 잘하는 일

도구 나열보다 판단의 품질을 드러내는 관점 위주로 정리했습니다. 그래서 어떤 팀에 들어가도 재사용 가능한 역량이 보입니다.

01

문제 정의를 먼저 고정

현상과 문제를 분리하고, 무엇이 진짜 리스크인지 먼저 구분합니다. 이 단계가 흔들리면 이후 실험과 지표 해석이 전부 엇나갑니다.

02

대표 지표와 행동 레버를 분리

대표 지표는 판단 기준으로, 행동 지표는 움직이는 손잡이로 다룹니다. 그래서 숫자가 움직였을 때 왜 움직였는지 추적이 가능합니다.

03

속도보다 해석 오류를 줄임

엣지 케이스, 측정 한계, 인과 착시를 먼저 점검해 잘못된 결론의 비용을 낮춥니다. 실행은 그 다음입니다.

Operating System

제가 일할 때 쓰는 기본 구조

PM, 마케팅, 데이터 업무를 따로 보지 않고 하나의 루프로 연결합니다. 이렇게 해야 보고서가 쌓이지 않고 실제 액션으로 이어집니다.

  1. 1

    Observe

    퍼널, 리텐션, 채널 성과, 사용자 반응에서 비정상 패턴을 관측합니다.

  2. 2

    Define

    무엇이 문제인지, 왜 중요한지, 어떤 지표가 대표해야 고정합니다.

  3. 3

    Validate

    행동 지표, 세그먼트, 엣지 케이스, 문서화로 해석 리스크를 점검합니다.

  4. 4

    Ship & Learn

    실행 후 결과를 해석하고, 다음 액션과 적용 범위를 함께 남깁니다.
